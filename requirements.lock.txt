# requirements.lock.txt — exact, reproducible dependency versions.
#
# ASVS-AUDIT.md finding #14: requirements.txt/pyproject.toml declare version
# *ranges*, which is what you want for a library/app spec, but it means two
# installs six months apart (or on two different machines) can silently end
# up with different actual versions — which is exactly what happened before
# this file existed: requirements.txt claimed pandas<3.0.0 while every real
# install in this repo was already running 3.0.x. This file pins every
# package (including transitive ones) to the exact version verified clean
# by `pip-audit` on 2026-09-15, so "what's actually installed" is reproducible
# and auditable from the manifest alone, without needing shell access to a
# running environment the way this audit initially did.
#
# Covers the full dependency closure of `pip install -e ".[fabric,dev]"` —
# core app dependencies plus the Fabric extra (pyodbc/azure-identity) and
# dev tooling (pytest/ruff/mypy) — resolved into ONE consistent set. If you
# only need the core runtime deps (no Fabric, no dev tools), install from
# requirements.txt instead; this file is for reproducing the full dev/CI
# environment exactly.
#
# Locked with Python 3.13 specifically (matching both this repo's actual
# dev .venv and the CI workflow's setup-python version) — NOT whatever
# `python3`/`python -m venv` happens to resolve to on your machine. The
# first attempt at this file was built under Python 3.14 and resolved
# numpy==2.5.3, which requires Python >=3.12 — installing it under CI's
# original Python 3.11 config failed outright. Pin the interpreter
# explicitly when regenerating, or you'll reproduce that exact break.
#
# To use:
#   pip install -r requirements.lock.txt
#
# To regenerate after bumping a version in pyproject.toml:
#   /path/to/python3.13 -m venv /tmp/lockenv
#   /tmp/lockenv/bin/pip install -e ".[fabric,dev]"
#   /tmp/lockenv/bin/pip freeze --exclude-editable | sort > requirements.lock.txt
#   pipx run pip-audit --format json  # (with PIPAPI_PYTHON_LOCATION set to
#                                       /tmp/lockenv/bin/python) — re-verify
#                                       clean before committing the update.
#
# Verified via `pip-audit` against this exact set on 2026-09-15: 0 known
# vulnerabilities. Re-run periodically — this is a point-in-time result, not
# a standing guarantee (a new CVE can be published against a version that
# was clean when this file was generated).
